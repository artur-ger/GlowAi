# Групповые результаты (GlowAi) — готовность к приёмке (горизонт: конец декабря)

**Проект:** GlowAi (№ С60)  
**Формат:** мобильное приложение анализа кожи и персонализированного ухода в путешествиях с учётом климата и локального рынка средств  
**Команда:** Мамедрзаев Заур (фаундер, ML/CV), Гулин Всеволод (продакт), Чепурных Артур (backend / mobile)  
**Источники семестра 1:** паспорт проекта, питч-дек, CustDev (~20–35 интервью по сегментам), БФТ, расчёт TAM/SAM/SOM, бизнес-модель Остервальдера  

**Трек:** обычный B2C (не корпстартап). Блок «финансовый эффект внедрения в компанию» не применяется.  
**Статус документа:** рабочий черновик группового отчёта.  
Зелёным отмечено то, что уже опирается на артефакты прошлых семестров; жёлтым — черновик, который нужно подтвердить цифрами/тестами; красным — обязательные пробелы до приёмки.  
**Инженерный статус:** каркас MVP в репозитории `c:\Glow_Ai` (FastAPI + Flutter).

## 1. Готовность MVP1 (пилотируемый продукт)

### 1.1. Целевой сегмент первого выхода
**Приоритет №1 — отпускники** (редкие путешественники, пляжный/курортный сценарий).  
Обоснование из артефактов: наибольшая острота «SOS на месте», freemium/разовая консультация, CustDev-приоритет №1.

### 1.2. Ключевые функции MVP (минимальный набор ценности)
1. **Symptom-first + CV-анализ кожи** по фото/описанию симптома.  
2. **Климатический модуль** (дом vs страна пребывания) → риски для кожи.  
3. **Персональный план ухода / packing-list** под маршрут.  
4. **Рекомендации с учётом доступности** (база SKU / локальный ассортимент — в MVP: топ-страны выездного турпотока).  
5. **Follow-up через 48–72 ч** (повторная оценка / коррекция рекомендации).

> Ценность MVP для пользователя: за минуты получить понятный план действий вместо 2–3 часов поиска/консультации и снизить риск покупки неподходящего средства.

## 3. Рабочая (продуктовая) гипотеза проекта

### 3.1. УЦП (из питча, для наследования в гипотезе)
> GlowAi — единственное приложение для путешественников, которое за считанные минуты создаёт персонализированный план ухода за кожей с учётом локального климата и доступных средств: высокая точность диагностики, локализация, простота, независимость рекомендаций от брендов.

### 3.2. Рабочая гипотеза для пилотирования (черновик к утверждению командой)
**Если** отпускнику перед поездкой или на месте дать MVP GlowAi (фото/симптом + маршрут → план ухода с учётом климата и доступных средств) **за ≤5 минут**,  
**то** ≥70% участников подтвердят применимость плана, а ≥25% будут готовы оплатить разовую SOS-консультацию / пробный PRO,  
**потому что** текущие альтернативы не учитывают travel-контекст и локальный рынок, а стоимость ошибки высока (время + деньги на неподходящие средства/консультации).

**Связь с УЦП:** гипотеза напрямую проверяет уникальные элементы УЦП — *скорость*, *персонализация под климат*, *учёт доступных средств*, *замена дорогих/долгих альтернатив*.

### 3.3. План пилота (методология эксперимента)
1. Рекрутинг 30–40 отпускников (TG/VK travel-сообщества, личные сети, партнёрские каналы).  
2. Онбординг + дисклеймер (не медуслуга).  
3. Сценарий A (до поездки) или B (на месте).  
4. Фиксация времени, скрина/лога результата, опроса ценности.  
5. Опциональный paywall-тест (намерение платить / тестовый платёж).  
6. Анализ → confirm / корректировка / pivot.

### 3.4. Предполагаемые результаты пилота
| Исход | Условие | Действие |
|---|---|---|
| Успешный старт | Пороги из §2.3 выполнены + нет блокеров доверия к CV | Масштабировать GTM на отпускников; готовить тестовые продажи 4 семестра |
| Корректировка | Ценность есть, но узкое место в UX / базе SKU / климате | Доработать MVP по бэклогу; уточнить УЦП (например, усилить SOS, ослабить packing) |
| Провал / пивот | Ценность не подтверждена | Пивот сегмента (лайфстайл/командировочные) или ядра ценности (убрать CV / усилить rule-based / B2B) |

### 6.5. Про «корпстартап» и финансовый эффект внедрения
В текущих артефактах GlowAi описан как **B2C travel-beauty продукт** с перспективой B2B.  
Если трек формально **корпстартап** (внедрение внутрь компании-партнёра), в отчёт нужно добавить отдельный блок:

> Предварительный финансовый эффект для компании-партнёра = экономия на X + прирост выручки/лояльности Y − стоимость внедрения Z.

Без выбранного корпоративного заказчика этот пункт закрыть нельзя — нужна развилка: (а) остаёмся B2C-стартапом и не тащим «эффект внедрения», (б) фиксируем партнёра и считаем эффект под него.

### 6.6. Обновление бизнес-модели Остервальдера

- способы монетизации, цены, ARPC;
