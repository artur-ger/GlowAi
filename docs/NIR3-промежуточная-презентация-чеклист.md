## 1. Групповые критерии (коэфф. 0,05 + 0,05 + 0,1 = 0,2)

### Проблема (0,05) — в питче почти ок, подтянуть формулировку

**Критерий:** боль в **одном предложении** + значимость **в цифрах со ссылками**.

**Готовая формулировка (вставить на слайд «Контекст и проблема»):**

> Путешественник не может быстро подобрать безопасный и доступный уход за кожей под климат поездки: консультации на месте дорогие и долгие, а интернет/нейросети не учитывают travel-контекст и локальный рынок средств.

**Цифры (оставить на слайде, с источниками внизу):**
- 17,4 млн турпоездок / суммарный поток 29,2 млн (АТОР / RST)
- проблемы кожи — 3-е место среди жалоб туристов
- консультация на месте ≈ 3 000 ₽ + ~2,5 ч; неверный подбор ≈ 2,5 тыс. ₽ + ~2 ч поиска
- 50–70% людей пользуются неподходящими средствами

**Риск для комиссии:** длинный абзац «наш продукт — первый…» смешивает проблему и решение. На слайде проблемы — **только боль + цифры**. Решение — следующий слайд.

### УЦП (0,05) — есть, но ужесточить под пилот-сегмент

**Критерий:** выгода для **конкретного сегмента пилота** + почему решение закроет боль.

**Формулировка под пилот (отпускники):**

> Для отпускников GlowAi за ≤5 минут даёт персональный план ухода и packing-list под климат маршрута и доступные на месте средства — быстрее и дешевле, чем консультация/поиск, и в отличие от Skinive / ChatGPT учитывает travel-контекст.

На слайде УЦП обязательно:
1. сегмент пилота = **отпускники**;
2. выгода = время + деньги + уверенность;
3. чем лучше альтернатив (климат + локальный ассортимент);
4. скрин/прототип MVP рядом.

### Гипотеза проекта (0,1) — в старом питче **НЕТ** (критический пробел)

**Вставить отдельный слайд «Рабочая гипотеза» (обязателен шаблоном):**

> **Если** отпускнику перед поездкой или на месте дать MVP GlowAi (симптом/фото + маршрут → план ухода с учётом климата и доступных средств) **за ≤5 минут**,  
> **то** ≥70% подтвердят применимость плана, а ≥25% будут готовы оплатить разовую SOS / пробный PRO,  
> **потому что** альтернативы не учитывают travel-контекст и локальный рынок, а цена ошибки высока.

Рядом на слайде — статус MVP: «каркас MVP готов (Flutter + FastAPI), пилот 30–40 пользователей — в работе / дата».  
Без этого критерий 0,1 не закрыть: гипотеза должна быть **проверяемой**, а MVP — «достаточен для проверки».

### Черновик под роль Mobile / Flutter (если это ваша зона)

**Роль:** Mobile-разработчик (Flutter) — клиент MVP, UX сценариев «до поездки» и «SOS на месте».

**Задачи 3 семестра:**
1. Flutter-клиент: анкета → маршрут → (опц.) фото → план ухода / packing-list.  
2. Интеграция с FastAPI (`/healthz`, analyze).  
3. UX дисклеймера «не медуслуга» + согласие на селфи.  
4. Смоук сценария ценности ≤5 мин для пилота гипотезы проекта.

**Личная проблема:**  
Пользователь не получает первую ценность MVP, если путь «анкета → план» долгий, неочевидный или требует обязательного селфи.

**Личная гипотеза (шаблон с метриками):**  
> Если упростить онбординг Flutter-клиента до symptom/маршрут-first (селфи опционально) и довести time-to-plan до ≤5 минут на пилоте 30 отпускников, то доля завершивших сценарий с оценкой «план понятен и применим ≥4/5» составит ≥70%, а доля отказов на шаге фото — ≤20%.

**Теоретическая опора:**
- CustDev семестра 1 (travel-контекст, скорость).  
- ВКРС-опрос: сильный спрос на packing/подготовку к поездке; доверие к себе > к приложению; селфи/CV не запрашивают.  
- Альтернативы: погода + ChatGPT без travel-skincare сценария.  
- UX-литература / практики time-to-value в consumer apps (кратко + ссылки).

**Методика (пошагово):**
1. Зафиксировать 2 сценария: A «до поездки», B «SOS».  
2. Прогон 5 внутренних smoke + `flutter analyze`.  
3. Пилот 15–20 пользователей на сценарии A (минимум для вашей гипотезы; общий пилот 30–40 — командный).  
4. Замер: время до плана, CSAT применимости, drop-off на фото.  
5. Вывод confirm / правка UX (убрать обязательное фото / сократить поля).

**Результаты сейчас (честно):**
- Клиент MVP в репозитории `mobile/`; ключевой экран `home_screen.dart`.  
- API smoke `/healthz` + analyze.  
- Полноценный пользовательский пилот — в плане (дата).

**Артефакты:** репозиторий GlowAi, `docs/user-docs.md`, `docs/privacy-photo.md`, PDF выводов ВКРС-опроса.

> Если ваша роль другая (продакт / ML / backend) — гипотезу нужно переписать под вашу зону. Пришлите роль и программу — перепишу блок 1:1 под слайды.

## 5. Быстрый проход «чтобы не докопались»

| Вопрос эксперта | Короткий ответ |
|---|---|
| Где гипотеза проекта? | Отдельный слайд, If–Then–Because + пороги 70% / 25%. |
| MVP готов к проверке? | Да для пилота: Flutter + FastAPI, сценарий план за минуты; EfficientNet/5000 SKU — вне MVP. |
| Чем не ChatGPT? | Нет связки климат маршрута + packing + дисклеймер + (план) локальный ассортимент в одном сценарии. |
| Где доказательства ценности? | CustDev 20–35; количественный пилот MVP — следующий шаг, метрики уже зафиксированы. |
| Почему отпускники? | Максимальная острота SOS + простая разовая оплата (из CustDev / питча). |
| Медицина? | Не медуслуга; дисклеймер в UI; фото не хранится. |
| Откуда цифры рынка? | Слайд источников + АТОР/RST, PubMed, расчёт TAM/SAM/SOM на листе 5. |
